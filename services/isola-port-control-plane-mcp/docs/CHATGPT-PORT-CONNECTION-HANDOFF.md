# ChatGPT connector handoff — Isola Port control-plane MCP (read-only)

## Endpoint

```
https://portmcp.epic.dm/mcp
```

**This is a placeholder.** The nginx + TLS reverse-proxy step that would
make this endpoint actually reachable from the internet has NOT been done
by this build. It requires a human (Phillip or whoever owns DNS/nginx on
the box) to:

1. Point DNS `portmcp.epic.dm` at the server running this MCP process.
2. Add an nginx server block (or equivalent) terminating TLS (Let's
   Encrypt / acme.sh — deepseek already has `.acme.sh` set up for other
   subdomains) and reverse-proxying to `127.0.0.1:8890`.
3. Run this MCP server itself under process supervision (systemd or pm2)
   so it survives reboots — **explicitly NOT the existing `/opt/bff-v2`
   pm2 instance**; this is a fully separate process/app.

Until that's done, this server only exists at `http://127.0.0.1:8890` on
the host it runs on and is not reachable from ChatGPT or anywhere else off-box.

## Auth

Bearer token, generated by the operator (Phillip), passed as:

```
Authorization: Bearer <MCP_BEARER_TOKEN>
```

**Honesty note on ChatGPT's connector UI:** ChatGPT's custom-connector /
"Actions" UI generally prefers OAuth (authorization-code flow) for remote
connectors, and Bearer/API-key auth is either a secondary option or not
supported at all, depending on which ChatGPT surface is used (custom GPT
Actions vs. the newer MCP connector UI). **What is actually implemented
here is a static Bearer token**, not OAuth. If, when Phillip goes to add
this connector, ChatGPT's UI requires OAuth and refuses a plain bearer
header, an OAuth wrapper (authorization server issuing short-lived tokens
that this server validates, or a thin proxy in front of it) is a **human
follow-up task, not something this build claims to have done.** Do not
treat this as solved until it's been tried against the real ChatGPT
connector UI.

## Step-by-step connection instructions (once the endpoint is live)

1. In ChatGPT, go to the connector/MCP settings area (Settings ->
   Connectors, or the custom GPT Actions builder, depending on which
   ChatGPT product surface is in use).
2. Add a new remote MCP server / connector.
3. Server URL: `https://portmcp.epic.dm/mcp`
4. Auth type: Bearer token (if offered) — paste the `MCP_BEARER_TOKEN`
   value Phillip generated. If only OAuth is offered, stop and flag the
   OAuth-wrapper follow-up above instead of forcing it.
5. Save and test the connection — ChatGPT should be able to call
   `tools/list` and see the 10 tools below.
6. Try one of the example prompts below to confirm it's live.

## The 10 tools

| Tool | What it does |
|---|---|
| `get_release_board` | Derived Release Train 01 board (composed from build_task/requirement/defect/epic_project — Port has no native release_gate blueprint). |
| `list_open_gates` | Release-board rows that are not yet green/done, with dependency notes. |
| `get_gate_evidence` | Evidence (description, evidence-type, last-updated, staleness) for one named gate. |
| `list_open_blockers` | Open defects + P0-MVP backlog tasks, ranked by severity. |
| `list_decisions` | All ratified/logged decisions, newest first. |
| `list_release_tasks` | All build tasks that aren't Done yet. |
| `list_pilot_readiness` | Honest pilot-readiness state; candidates list is always empty (none named in Port yet) — never returns customer content. |
| `list_recent_port_activity` | Recent activity across allowlisted entity types (audit log if Port exposes it, else derived from $updatedAt). |
| `get_entity` | Fetch one entity by id + blueprint (blueprint must be on the allowlist). |
| `search_port` | Contains-match search by identifier/title across allowlisted blueprints. |

## Disable / revoke

If this needs to be shut off:

1. **Kill the process.** `ps aux | grep dist/server.js`, then
   `kill <pid>`. (If running under systemd/pm2 per the human setup step
   above, use that supervisor's stop command instead.)
2. **Rotate `MCP_BEARER_TOKEN`.** Generate a new one
   (`openssl rand -hex 32`), update the running server's environment, and
   restart it. Any client using the old token is immediately locked out.
3. **Revoke the Port credential.** In the Port UI, go to the
   organization's API credentials / access-control settings and revoke or
   rotate the `PORT_CLIENT_ID`/`PORT_CLIENT_SECRET` pair this server uses.
   This is the backstop even though this server's own code enforces
   read-only-ness independently of Port's credential scoping (see
   `docs/SECURITY-REVIEW.md`).

## Audit log location

`data/audit.log` (JSONL, append-only, relative to the repo root on
whichever host runs this server — currently
`/home/epicdm/isola-port-control-plane-mcp/data/audit.log`). Each line
records `{timestamp, tool, callerRef, paramsHash, resultCount, ok}`.
`callerRef` is a hash of the bearer token, never the raw token. No
secrets or response bodies are ever written to this file.
